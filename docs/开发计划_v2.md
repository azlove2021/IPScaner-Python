## 〇、一句话结论

项目里有**两条代码线**，绿色版 exe 是**较新的一条**，但它没有可用的源码；
`src/` 是较旧的一条，但源码完整可编辑。
实测证明二者**同源**：`src/` 用 Python 3.10 编译后有 **176 个 code 对象与绿色版逐字节相同**。
所以"找回绿色版源码"这件事**不需要从零重写**，只需要补齐差集。

## 三、Phase 2：端口扫描性能 —— ✅ 已完成并验证

### 根因（实测，不是猜的）

```
scan_ports_async  ──try──▶  _scan_ports_async ──▶ 裸 import asyncio
        │
        └──except Exception──▶  _scan_ports_thread（线程池兜底）
```

`asyncio` 在打包清单里被排除了（`--exclude-module asyncio`），
所以裸 `import asyncio` 必抛 `ModuleNotFoundError`（是 `Exception` 的子类），
被 `scan_ports_async` 的 `except Exception` **吞掉**，静默退化到线程池。

**不崩，但慢约 24%（22s → 29s）。** 这也是为什么这个 bug 一直没被发现。

冻结环境实测佐证：`has_asyncio = False`。

### 已实施

同模块里现成的 `scan_ports_fast`（非阻塞 socket + `select`）不需要 asyncio。
两者签名不同（8 参 vs 7 参），**不能简单改别名**，做了适配：

| `scan_ports_async` 形参 | → `scan_ports_fast` |
|---|---|
| `ip, ports, timeout_ms` | 同名透传 |
| `concurrency` | → `batch` |
| `low_threshold` | 无对应（`fast` 不做低端口分档） |
| `cancel, on_port, progress` | 同名透传 |

任何异常都回退原实现，**保证不比修复前更差**。

| 模块集合 | 与绿色版 PYZ 比对，**缺 0 个** |

### 踩坑

> [!warning] 坑：照抄 `slim.spec` 的裁剪清单会**过度裁剪**
> `slim.spec` 里排了 `decimal` / `_decimal`，但 `mainform.scale_img` 里有
> **延迟** `import fractions`，而 `fractions → decimal → _decimal`。
> 静态分析扫不到函数体内的延迟导入，构建期不报错，**启动即崩**：
> `ModuleNotFoundError: No module named 'decimal'`。
>
> 对照绿色版 PYZ 才发现它**带着** `decimal` / `_pydecimal` / `fractions` / `numbers` / `statistics`，
> `_internal` 里也带 `_decimal.pyd` —— 说明绿色版用的清单**没排 decimal**。
>
> **解法**：从 EXCLUDES 移除 `decimal`/`_decimal`，并把
> `decimal, _pydecimal, contextvars, fractions, numbers, statistics` 显式写进 `hiddenimports` 兜底。
> 这条正好印证了旧笔记坑 2 的教训：**裁剪后必须跑功能，不能只看"能不能启动"。**

> [!warning] 坑：PyInstaller 的 tk 钩子要 `tcl/tcl8` 目录
> 嵌入式 Python 缺 `tcl/tcl8`（tcl 平台模块目录），钩子只报一行 WARNING 就跳过，
> 结果 **tcl 数据一个都没进包**。从绿色版 `_internal` 把 `tcl8`（8.4/8.5/8.6）拷到
> `<py>/tcl/tcl8` 后正常（tcl 830 项 / tk 87 项 / tcl8 5 项）。

> [!warning] 坑：冻结版 stdout 走 8KB 块缓冲
> 诊断用的 `print` 一句都读不到（不是 tty）。**诊断信息要写文件，不要 print。**

## 五、后续主线：Phase 3 —— 90 个绿色独有函数回灌 `src/`

这是**唯一还欠着的大块**，也是让项目重新变成"可维护源码"的必经之路。

### 为什么必须做

现在的单 exe 是从 `.pyc` 打的 —— 能跑、能发人，但**改不动源码**。
每加一个功能都要回到字节码上去做手术，不可持续。

### 怎么做（已有可收敛的工程回路）

```
pycdc 反编译  →  repair.py 机械修复  →  Py3.10 编译
      →  与绿色版 pyc 逐字节比对  →  不匹配的逐个修  →  重复
```

**关键：判据是客观的**（逐字节相同即完成），不存在"看着差不多就行"。

已具备的工具：

| 工具 | 作用 |
|---|---|
| `repair.py` | 修复 pycdc 的两类系统性缺陷：**99 处 kwargs 丢失**（`f(v,**('k',))` → `f(k=v)`）、列表/生成器碾平 |
| `dis_fn.py` | 按限定名反汇编指定函数，人工修补时的**真值依据** |
| `verify_recovered.py` | L1/L2/L3 三档结构等价判定（收敛判据） |
| `geom_check.py` | 窗体几何断言（防布局回退） |

### pycdc 的已知上限（不要重复踩）

- **master 与 2023-04 旧版都处理不了 `JUMP_IF_NOT_EXC_MATCH`**（try/except）。
  旧版在 `mainform` 上还会**死循环**，产出过一个 **2 GB 的 py 文件**。
- 实测产出：7 个模块共 2538 行、51 个 `# WARNING: Decompyle incomplete` 标记、
  ~30 个 `<NODE:n>` / `None(...)` 缺陷。机械修复后**仍有 3 个模块编译不过**，
  断点形态固定（`λ .0` 生成器、丢失的调用名、丢失的控制流块头）。

> [!note] 因此 Phase 3 的正确姿势
> **不要指望 pycdc 一次出可编译的完整源码。**
> 拿它当"骨架 + 常量 + docstring 的来源"，断掉的部分用 `dis_fn.py` 对照字节码手工补。
> 优先做**新功能**（90 个独有对象），36 个"同名不同"的留到最后——它们多数只是被新功能牵连改动。

### 建议顺序（按"价值 / 成本"排序）

| 顺序 | 目标 | 对象数 | 理由 |
|---|---|---:|---|
| 1 | `gui.Config` 的 4 个方法 + Config 类 | 3~7 | 配置持久化是**基础能力**，其余功能依赖它；代码量最小 |
| 2 | `core` 的 DIY 命令组 | ~6 | 纯 IO + 解析，无 try/except，pycdc 大概率一次过 |
| 3 | `core` 的 `scan_ports` 全家桶 | ~20 | 用户能直接感知（性能/扫描能力）；但要小心 try/except 区 |
| 4 | `dialogs` 的 `f_diy` + IP 历史 | ~15 | 表单代码，坐标全是字面常量，pycdc 出得比较全 |
| 5 | `dialogs.f_ipsegment` 的 5 个子函数 | ~10 | 已有一份完整字节码几何，可交叉验证 |
| 6 | `mainform` 的缩放 + 菜单栏重绘 | ~7 | 与主 Canvas 绘制耦合，风险最高，放最后 |
| 7 | 36 个"同名不同"的对齐 | 36 | 等前面都定了再回头看，多半已自动对齐 |

## 状态更新：2026-09-29 第二轮（v1.25.2）—— 用户退回截图后的补修

用户拿 v1.25.1 的截图回来：「**你修复了个什么，这里的字不还是看不到吗**」，
红箭头指着工具条那一排按钮。第一轮确实**漏了这一块**，已补修并交付。

### 漏检原因（比 bug 本身更值得记）

1. `ui_audit.audit_canvas()` 只采集画布文本的字体/字号，**根本没算对比度**
   → 主画布上「白字压浅面」永远不会告警，汇总里的「低对比 0」是**假通过**。
2. 审计只判「越界/裁切」，而按钮面**飘到菜单栏那一行**不算越界（它只是画在别处）。

### 缺陷

工具条按钮 = 1 个 polygon（面）+ 1 个 text（字），**坐标系不一致**：
面按 `设计 1:1` 画（`(176,41)-(234,65)`），字按 `设计×S` 画（`(284,70)-(328,91)`）。
S=1.5 时面比标签高 21px → 整排彩色块飘到菜单栏上，白字落在窗体底色 `#F4F6F8` 上（对比度 **1.00**）。
判据：6 个按钮的「实测色块 x0 ÷ 设计 x」恒为 **1.00**（若已缩放应为 `1/S=0.667`）。
带钩子/不带钩子 A/B 完全一致 → **绿色版原有缺陷**，不是修复层引入。

### 修法

1. `cv.scale(item,0,0,S,S)` 把面搬回 `设计×S`；
2. 按面的真实亮度定字色 —— 白字落在 `#0078D4/#E15B5B/#34C77B` 上是
   `4.53/3.59/2.19`，必须改；改 `#000000` 后 `4.64/5.85/9.60`。
   **不能反过去压暗面色**：`C_SKYBLUE` 等同时是 IP 格子状态色（截图里 `#A9D8F2` 有 39.5 万像素）。
3. 顺手修本机 IP 格橙字 `#F26B1D` on `#A9D8F2` = **2.00** → 同色相压暗 `#914011` = **4.68**。
